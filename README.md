# 大促 GMV 归因与备货 · 口径与方法包

大促复盘最常见的两种错误：**把「流量涨了」当成全部原因**，**把「品类结构升级」算成「运营提效」**。

这个仓库用两个恒等式把它们拆开：GMV 拆成客流 × 转化 × 客单，再把转化与客单拆成「自身变化」与「结构变化」，
最后把归因结果接到备货上。所有结论都能在 Notebook 里跑出来。

```bash
pip install -r requirements.txt
python scripts/run_notebooks.py     # 跑出 Notebook 的全部输出
pytest tests -q                     # 5 个测试，验证分解闭合与结构拆分
```

---

## 一、这个项目回答什么

2025 双 11 GMV 同比 **+60.4%**。复盘会上有两个说法：

- 运营说：「因为我们加大了投放，流量涨了。」
- 产品说：「因为凑单机制做得好，客单价涨了 43 块。」

两个说法都对了一半，但都漏了最关键的部分。这个项目要给出**可加总、可闭合**的答案。

| 结论 | 数值 |
|---|---|
| GMV 同比 | **+60.4%** |
| 客流效应 | 28.7% |
| 转化效应 | 25.8% |
| 客单效应 | **45.5%** |
| 分解闭合误差 | **0.00 元**（恒等式，应恒为 0） |
| 客单价增长中「结构」贡献 | **35.8%**（15.3 / 42.8 元） |
| 增量集中度 | 数码 + 美妆 = **59.9%** |
| 缺货率 12% → 5% 的代价 | 库存 +**9.4%** |

**一句话结论**：客单贡献最大，但其中三成半是「贵的品类卖得更多」，不是「同品类卖得更贵」。
照后者去优化凑单，下一次一定不及预期。

## 二、两个恒等式

### 2.1 三层分解（零残差）

```
GMV = UV × CVR × AOV

ΔGMV = ΔUV·CVR₀·AOV₀   ← 客流
     + UV₁·ΔCVR·AOV₀   ← 转化
     + UV₁·CVR₁·ΔAOV   ← 客单
```

这不是模型，是代数恒等。所以 `closure_error` 必须为 0——**如果它不为 0，说明口径没有对齐，
而不是「模型拟合得不好」**。真实项目里报的「误差 3% 以内」，误差全部来自口径
（退款剔除、跨端去重、定金尾款归属），公式本身不会产生残差。

### 2.2 结构与自身（shift-share）

```
CVR_total = Σ w_c · CVR_c        w = UV 份额
AOV_total = Σ v_c · AOV_c        v = 订单份额

Δ = Σ (w₁ - w₀)·指标₀  +  Σ w₁·(指标₁ - 指标₀)
     结构效应 mix            自身效应 within
```

**权重口径必须分开**：转化率的分母是流量，用 UV 份额；客单价的分母是订单，用订单份额。
用错权重会得到一堆看着合理、实则反向的结论。

## 三、备货接在归因后面

归因告诉我们「增量从哪来」，备货要回答「该备多少」。做法是先定服务水平，再反推备货：

```
Q = μ·(1 + k·CV),   缺货率 = 1 - Φ(k)
```

| 目标缺货率 | 安全系数 k | 备货量指数 | 库存金额（万元） |
|---|---:|---:|---:|
| 20% | 0.842 | 1.22 | 3,188 |
| 12% | 1.175 | 1.31 | 3,416 |
| 5% | 1.645 | 1.43 | 3,737 |

12% → 5% 要多备 **9.4%**。这个取舍由业务定：缺货损失 GMV 与体验，压货损失现金与折损。
分析师的活是把曲线算准，不是替业务选点。

## 五、环境

只依赖 `pandas` / `numpy` / `matplotlib` / `jupyter`。分解与备货换算都是解析式，没有机器学习依赖。

## 六、局限（主动说）

1. **拆的是会计恒等式，不是因果**。它回答「增量由哪几块构成」，不回答「如果不做大促会怎样」。
   后者需要地理对照或合成控制。
2. **数据是同构的**，闭合误差恰好为 0；真实项目里误差 2%~5%，来自口径而非公式。
3. **备货用正态近似**，真实需求有厚尾与断档，建议改用历史分位数或模拟法。
4. **没算缺货的实际损失**——缺货率到 GMV 损失之间还差一个「替代购买率」，本项目没有这个数据。
